# v5 引擎详细架构设计
> 基于 soul-knight-demo 验证机制 + v5 11模块体系 | 2026-08-25

## 1. 渲染管线：双模式统一
现有的 render 模块(canvas-engine.js)只支持等距(isometric)。需要扩展为双模式：
  - iso 模式：等距菱形瓦片，用于开放世界/学院枢纽
  - grid 模式：正方形网格瓦片，用于地牢/塔防/探索
切换方式：boot.render.setMode('iso'|'grid')，内部切换绘制逻辑。
两者共用：粒子系统、飘字、相机(参数不同)、视差背景。

## 2. 战斗系统：可插拔演法
现有 battle/index.js 混合了回合制答题 + M1实时战斗。需要拆为：
  core/battle/turn-based.js    — 回合答题(保留，用于结算检验)
  core/battle/realtime.js      — 实时战斗引擎(从soul-knight-demo提炼)
  core/battle/演法/             — 8种演法各一个子模块
    melee.js    — 近战扇形判定(已验)
    ranged.js   — 远程追踪弹道(已验)
    rhythm.js   — 节奏抓时机(待建)
    puzzle.js   — 配方/合成/塔防(待建)
    text.js     — 文字冒险/拼写(待建)
    dodge.js    — 闪避/走位(已验)
    stealth.js  — 潜行/影响环境(待建)
    boss.js     — 多阶段BOSS(待建)
每个演法导出: { init(enemyConfig), update(dt, player, enemies), getResult() }

## 3. 知识点→怪物映射(bestiary生成器)
核心函数: buildMonsterFromKnowledge(kpId) -> monsterConfig
输入: 知识点 id(如 phy_k3 = 牛顿第三定律)
输出: { name, icon, hp, atk, moves:[{kind, phases, onImpact}], stanceReq, knowledgeId }
映射规则(存储在 content/subjects/*.json 的扩展字段):
  - subject -> 场馆(phy->雷霆殿 chem->丹鼎峰)
  - grade -> 难度层级(10=高一 easy, 11=高二 normal, 12=高三 hard)
  - knowledge.kind -> 演法类型(collide=格挡演法, accel=走位演法, oscillate=节奏演法...)
  - knowledge.formulas -> 弹道参数/节奏BPM/合成配方
实现: content/subjects/*.json 每个知识点增加 kind 和 params 字段。
已知 M1 三怪(phy_k1~k3)已经验证了 collide/accel/oscillate 三种演法。

## 4. 游戏页面架构(不再是独立HTML)
每个场馆不是独立页面——是一个 'venue' 对象挂到 boot，通过 boot.world.enterScene(venueId) 切换。
  v5/index.html          — 学院枢纽(isometric开放世界)
  v5/venues/thunder.js   — 雷霆殿(物理,grid模式地牢)
  v5/venues/alchemy.js   — 丹鼎峰(化学,grid模式炼金台)
  v5/venues/math-tower.js— 推衍宫(数学,grid模式塔防)
  v5/venues/geo-explore.js—山河阁(地理,grid模式探索)
  v5/venues/literary.js  — 文渊阁(语文,DOM+Canvas混合)
  v5/venues/word-arena.js— 译灵堂(英语,DOM+Canvas混合)
所有 venue 统一通过 boot 读 state/input/knowledge/economy，不各自造轮子。

## 5. 学习→游戏 反馈闭环
战斗胜利 -> knowledge.recordAnswer(correct) -> 熟练度变化 -> 影响下次出题难度和怪物属性
具体链路:
  玩家击败怪物 -> battle emit 'battle:end' {win, knowledgeId}
  -> knowledge.recordAnswer(true, knowledgeId) -> proficiency[kpId]++
  -> 如果 proficiency 达到阈值 -> addChapterProgress() -> 通关章节
  -> 下一次 genFloor() 时根据 proficiency 调整深度和怪物难度
  -> 结算时 getQuestion(difficulty) 根据 proficiency 自适应出题
