## 0. 愿景

一句话: **把《问道修仙学院》从一个"文字感、AI 味、枯燥"的伪开放游戏, 重做成一个"真正能装进口袋的大世界修仙学院": 玩家在地图上走格、抽卡、打音游、组卡组、下 Roguelite 副本、炼丹养灵宠, 同时把高三 6 门学科的考点矩阵以"练习 + 错题 + 复习"的闭环长进脑子里。**

v5 与 v4.4.0 的根本区别, 三个关键词:

1. **大世界 (Open World)** —— 从单页 HTML 改为 isometric 2.5D 世界地图 + 区域解锁 + 真实走格;
2. **小游戏驱动 (Mini‑Game Driven)** —— 教学动作不再只通过"答题", 而是分散在 12+ 个不同玩法里 (音游/卡组/Roguelite/桌游…) 让"学"被"玩"包裹;
3. **考点图谱 (Knowledge Graph)** —— 抛弃题海, 用 6 学科 × 7 分支 × ≥5 考点 = 210 个知识点的图谱 + 遗忘曲线驱动错题复习, 可被外化给老师/家长。

### 体验目标 (8 项, 每项可测试 / 可观测)

| # | 目标 | 测试方法 |
|---|---|---|
| E01 | 首屏 → 进入第一场玩法 ≤ 30 s | Lighthouse TTI + 手测秒表 |
| E02 | 单局玩法 (音游) 3 分钟闭环, 答题量 ≥ 20 题 | A/B 自动机 100 场 |
| E03 | 错题 24h 后自动复习提醒准确率 ≥ 85% | 模拟遗忘曲线 |
| E04 | 移动端 360x640 不卡顿, FPS ≥ 50 | 真机 + DevTools |
| E05 | 老玩家 v4 存档 100% 字段覆盖到 v5 | F01 冒烟 |
| E06 | 任意知识点都有 ≥3 种玩法可练该点 | 知识图谱→玩法映射表 |
| E07 | 60 分钟内可达成一次"完整闭环": 学习 → 战斗 → 资源获取 → 出战 → 击败 Boss | 端到端脚本 |
| E08 | 立绘/字体/谱面 100% 合法可商用 | 版权台账 + 自检脚本 |

## 1. 玩法体系 7 层

### 1.1 世界地图

走格 isometric 大地图, 7 个学科对应 7 块大陆 (雷震殿/丹鼎峰/山河阁/文渊阁/推衍宫/译灵堂/生灵圃), 加上中心"问道书院"主城. 玩家日登录默认从主城出发, 选路进入任一大陆; 大陆之间由"跨海飞舟" (答题过桥 + 资源消耗) 连接。

学习映射: 单科进度 → 解锁大陆第 N 区关卡 (例: 数学函数薄弱 → 推衍宫第 3 区"对数函数峰"始终未解锁)。

### 1.2 宗门系统

宗门 = 学校 (班级). 内门弟子 = 学校前十/单科拔尖; 外门弟子 = 普通在学; 掌门 = 学年前 1%. 玩家申请宗门、贡献度 (答题正确率×学科难度) 提升位阶. 宗门有公共灵田, 周贡献排名触发"宗门大赛"。

学习映射: 月考/模考排名 → 宗门位阶; 宗门任务 = 班级作业。

### 1.3 副本

6 学科技能副本 (固定套路, 主线) + 周轮换活动副本 (Roguelite). 单副本 5–8 关, 每关含 3 场迷你战斗 + 1 处资源事件; 通关解锁"副本图鉴"和"对应知识点的 1 星到 5 星难度梯度"。

学习映射: 高考真题 → 标准副本 (5 ★ 真题, 1 ★ 入门)。R 值 (复习系数) 越高的知识点 → 越优先排进副本。

### 1.4 修炼

修炼 ≠ 刷怪. 修炼 = "知识点内化": 玩家选 1 知识点, 进入该点的"内化塔", 12 层题 (难度逐层 1→5 星), 通关获 1 点"道行" (道行 = 知识点掌握度)。每日上限 3 次, 防止无脑肝。

学习映射: 单点突破 → 对应高考第 N 题型的稳态得分提升。

### 1.5 社交

轻量合作 + 半 PvP. 同宗门可"借灵宠" (互送 7 天 buff); 跨服天梯"道衡榜" (按 ELO)。聊天走本地 IndexedDB 消息队列 + WebRTC 假数据 (无后端)。

学习映射: 同伴竞争 → 学习自驱; 不直接关联考点。

### 1.6 商店

三类: 灵材 (练级)、丹方 (错题模板)、灵宠蛋 (学习伙伴系统)。价格 = 灵石/师门贡献度, 可用"答题正确率 + 日均时长"折算。

学习映射: 错题数量 → 错题丹方可用次数 → 复习深度。

### 1.7 进度

总进度 = 知识图谱覆盖率 × 道行点数 × 副本通关数 × 立绘解锁. 进度条驱动解锁: 道童 → 外门 → 内门 → 掌门 → 道衡真人。进度的可视化 = "问道路"折线 + "知识点雷达图"。

学习映射: 高考倒计时 → 进度百分比 = 各科复习覆盖率。

## 2. 小游戏池 (12)

> 字段: 玩法/教育映射/技术栈/可重用度 S%/工作量/绑定点. 工时基准: S=½ sprint, M=1 sprint (1 PR+1 测试+1 文档), L=2+ sprint。

#### 2.1 #01 桌游走格 (hullqin 借鉴)

- 玩法: hex 16 格棋盘, 玩家投骰走格, 落点触发答题/事件/商店. 答对 +1 buff, 答错 -1 HP. 12 回合胜利 = 通关一本"功法"。
- 教育映射: 任何学科分支都可灌入 (题包 hot‑swap), 难度梯度按格子深度对应 1–5 星。
- 技术栈: Phaser 3 (tile + z‑depth) — 已选定。备选: 自写 Canvas (L 风险)。
- 可重用度: 75% (动画骨架/骰子 RNG/事件总线被 2.2 音游 2.4 Roguelite 共享)。
- 工作量: M。
- 绑定点: 进入任何学科大陆的入口关; 也是"问道书院"日常玩法。

#### 2.2 #02 音游 (节奏术力口对标)

- 玩法: 4 轨道下落式 note, 谱面 JSON 自制。判定线 = 答题判定: 完美击 → 题目满分; Good → 1 题错误; Miss → 2 题错误。谱面音轨主题关联学科 (物理=匀速直线, 化学=滴定曲线节奏)。
- 教育映射: 实验步骤 / 时间序; 数形结合; 物理光学波长频率。
- 技术栈: WebAudio + 自谱面 JSON — 已选定。备选 Tone.js (但体积↑)。
- 可重用度: 60% (音频 engine / note pool 被 2.11 角色养成转场复用)。
- 工作量: M。
- 绑定点: 推衍宫 (数学+物理) + 丹鼎峰 (化学实验节奏)。

#### 2.3 #03 卡组构筑

- 玩法: 起手 5 张"法术卡", 每张卡 = 1 道高频考点 (例: 三角函数和差化积). 卡牌使用耗灵力, 灵力 = 分钟预算. 与 Boss 战回合制交替。
- 教育映射: 知识点联想/迁移; 错题 → 自动入卡。
- 技术栈: 自写 Canvas (无依赖), 手牌/弃牌堆/状态机纯 JS — 已选定。备选 Phaser (过度重)。
- 可重用度: 70% (牌组状态机/AI 决策树被 2.5 Boss 战直接用)。
- 工作量: M。
- 绑定点: 金丹期以上解锁, 玩家进入 Boss 战前强制组卡。

#### 2.4 #04 Roguelite 地下城

- 玩法: 每次随机地图 (WFC 生成 16x16 tile), 随机 3 关 + 1 boss, 每关 5 场答题. 死亡即重来但保留"传承" (解锁过的小奖励在下次继承)。
- 教育映射: 综合题/题组 (高考压轴题), 跨章节联想。
- 技术栈: Phaser 3 tile‑map + 简易 Dijkstra — 已选定. 地图生成自写。
- 可重用度: 80% (复用走格地图生成 + 卡组牌池 + 音游音频池)。
- 工作量: L。
- 绑定点: 周活动副本主体。

#### 2.5 #05 Boss 战策略

- 玩法: 3 选 1 回合制, 每回合出 1 题 + 3 个技能选项, 选对了进入下一回合, 选错 Boss 攻击。 12 回合击败。
- 教育映射: 题组 / 真实高考综合大题 / 题干长阅读。
- 技术栈: 自写 Canvas + 文本 DOM — 简单, 已选定。
- 可重用度: 90% (与 2.3 共用 AI 状态机, 与 2.12 共用答题渲染)。
- 工作量: S。
- 绑定点: 每个学科最后一关/宗门赛/赛季活动核心。

#### 2.6 #06 联机合作 / 竞技场

- 玩法: 双人合作 (WebRTC) 同打一只 Boss, 题目共享; 竞技场 (ELO) 1v1 答题, 同时限时的速度型 PvP。
- 教育映射: 协作解题 / 同伴讲解 (协作模式强制双方都必须解释自己的思路) — 学习科学上有 evidence。
- 技术栈: WebRTC (本地假数据, 单沙箱即可演示) — 已选定。备选 yjs (需轻服务, 暂弃)。
- 可重用度: 40% (协议栈独立)。
- 工作量: L。
- 绑定点: 宗门赛跨服; 周末道衡榜 1v1。

#### 2.7 #07 资源经营 (炼丹 + 灵植)

- 玩法: 炼丹 = 错题本 (3 错题合 1 丹 = 复习 1 次); 灵植 = 长期记忆 (种下一题, 7 天后"成熟" = 7 天后再考 1 次)。每日定时看护, 自动化队列。
- 教育映射: 遗忘曲线; 间隔复习 (Spaced Repetition); 主动回忆。
- 技术栈: 自写 + IndexedDB 调度器 — 已选定。
- 可重用度: 65% (调度器共享 2.1 日常队列)。
- 工作量: M。
- 绑定点: 玩家主城"洞府"固定入口。

#### 2.8 #08 拼图 / 数独 / 数形结合

- 玩法: 3x3 至 6x6 数学拼图; 数独 (4/9 宫); 数形结合 (几何题配画板操作)。完成度 = 知识点熟练度。
- 教育映射: 几何直觉 / 排列组合 / 数列规律。
- 技术栈: 自写 Canvas + 触摸 — 已选定; 几何用 matter.js 微模块。
- 可重用度: 50% (画板子模块被 2.9 复用)。
- 工作量: M。
- 绑定点: 推衍宫 + 文渊阁 (数形语文)。

#### 2.9 #09 物理模拟 / 化学实验

- 玩法: 拖拽器材拼装电路, 化学拖拽元素周期表配平反应, 实时沙盒模拟 p5.js / matter.js. 答完后系统提示"对/错" + 关联考点。
- 教育映射: 实验题 / 电学 / 反应原理 / 工业流程。
- 技术栈: matter.js (物理) + 自写 canvas (化学) — 已选定。
- 可重用度: 55% (画板 + RNG)。
- 工作量: L。
- 绑定点: 雷震殿 (物理) + 丹鼎峰 (化学实验题) 必玩。

#### 2.10 #10 文字 AVG + 选择题链

- 玩法: 全屏立绘 + 文字气泡, 关键决策点出选择题 (选对了剧情继续, 选错了分支). 30 分钟一章。
- 教育映射: 阅读理解 + 文言文 + 英语完形 + 历史背景 (复用为剧情背景)。
- 技术栈: 原生 DOM + Web Speech API (TTS 朗读) — 已选定。
- 可重用度: 70% (对话引擎/分支决策树与 2.11 复用)。
- 工作量: M。
- 绑定点: 主线剧情; 每学科"开山祖师传"独立章节。

#### 2.11 #11 角色养成

- 玩法: 服饰 (12 种职业服 + 60 种时装)、称号 (道行/N 节点解锁)、头像 (12 套立绘)、二次元立绘 (5 张关键 NPC); 与学习里程碑挂钩。
- 教育映射: 不直接绑定考点, 但给"持久动力": 5 ★ 通关某副本 → 解锁限定立绘。
- 技术栈: 自写 Canvas 拼合 + spine‑runtime lite — 已选定。
- 可重用度: 40%。
- 工作量: M。
- 绑定点: 主城"衣帽间"; 任意玩法结算面板。

#### 2.12 #12 答题快闪 (60 秒刷题)

- 玩法: 60 秒倒计时, 自动从考生 5 ★ 错题里出随机题, 答对 +1 答错 -1 (含难度系数). 排行榜 (本地 + 假数据云端)。
- 教育映射: 应试速度; 限时压力下的准确率。
- 技术栈: 原生 DOM — 已选定。
- 可重用度: 90% (与 2.5 共用答题渲染与计时器)。
- 工作量: S。
- 绑定点: 每日任务 / 修仙试炼 (限时周活动)。

总工时估算: 12 个小游戏合计 ≈ 5 sprint (M 数 = 7, S 数 = 3, L 数 = 3 → 7+3+3×2 = 16; 双人 pair 编程约 ½)。

## 3. 视觉 / 技术栈选型

### 3.1 主渲染

| 候选 | 优势 | 风险 | 判定 |
|---|---|---|---|
| Phaser 3 + isometric tile | 社区大/文档全/移动端成熟; 自带 physics/input/tilemap | 30 KB gz, 启动 200 ms | ✅ **选定** |
| 三选项: 自写 Canvas + tiledata JSON | 极小 (< 10 KB), 完全可控 | 开发成本↑×3 | 备选, 仅 SP1 PoC |
| Three.js 3D 简易 | 视觉震撼 | 移动端 GPU 100%+ 命中率, 不适合校园场景 | ❌ 不选 (高考用户 360p 手机占有率高) |

### 3.2 音频

| 候选 | 优势 | 风险 | 判定 |
|---|---|---|---|
| WebAudio + 自谱 JSON | 0 依赖, 可控版权 (自制), 包体小 | OGG 体积↑×1.5 | ✅ **选定** |
| Tone.js | 多轨/MIDI 强 | +40 KB, 商业谱面授权复杂 | 备选, 仅 2.2 音游复杂谱面 |

### 3.3 网络

- 选定: **WebRTC 假数据 (单沙箱)** — Demo + 单机可用, 无后端, 满足 v5.0 验收。
- 备选 (v6.0): yjs + 自托管轻服务 (Node + SQLite)。

### 3.4 存储

- 主存档: **IndexedDB** (取代 v4 的 localStorage, 解决 v2 4MB 配额上限)。
- 短期: localStorage 仍保留 UI 偏好 (字号/主题/音效开关), ≤ 64 KB。
- 与 v4 兼容: 启动时检测 `wendao_save_v2` → 一次性导入 → 写 `wendao_save_v3` + 备份键 `wendao_save_v3_migration_<ts>`。

### 3.5 字体

- 选用 **思源黑体/思源宋体/思源柔黑 (SIL OFL 1.1 免费商用)**。
- CJK 不嵌入完整字体子集, 仅子集化 2500 字 + 备用 OTF (按需 lazy load)。
- 风险: 中日韩文字符总数多, 子集不全导致某些生僻字回退, 需保留系统默认 fallback。

### 3.6 立绘

- v5.0 占位用 CC0/MIT 美术 (例: openpeeps / pixiv 允许转载的 CC‑BY 立绘) + 自绘简笔 SVG。
- 二次元立绘商业使用法律风险: 严格走 CC0 / 公共领域 / 自制。
- 兜底: 全部失败则只用 SVG + 表情符号 (emoji) head — 不影响玩法。

### 3.7 物理模拟

- 选定: **matter.js** (2D physics, 50 KB)。
- 3D 不采用, 避免复杂度。

### 3.8 包分发

- 仍 zip 一份 (与 v4 一致)。
- `index.html` 作为启动器 → `boot.js` (新) → 按需 lazy load 其他模块。
- CDN 不依赖: release 资产全静态, 解压本地 HTTP 即可玩。

## 4. 题目库分类 / 数据 schema

### 4.1 学科树 × 7 分支 × ≥5 考点 = 210 考点

#### 4.1.1 语文 (7 分支)

- **古诗**
  1. 必背 75 首
  2. 意象与典故
  3. 律诗/绝句格律
  4. 诗人流派 (山水/边塞/田园)
  5. 高考默写高频 30 句
- **文言**
  1. 24 篇课内文言
  2. 词类活用
  3. 文言虚词 (之/乎/者/也/而/以)
  4. 文言句式 (判断/被动/倒装)
  5. 文化常识 (官职/科举/礼俗)
- **现代文**
  1. 论述类文本
  2. 文学类文本 (小说/散文)
  3. 实用类文本 (新闻/传记)
  4. 文章结构与思路
  5. 关键句含义
- **作文**
  1. 命题作文
  2. 任务驱动型作文
  3. 材料作文
  4. 议论文结构
  5. 应用文 (书信/通知/倡议)
- **字音字形**
  1. 多音字辨析
  2. 形近字辨析
  3. 易错字 3500
  4. 音形义统一
  5. 方言区高频错音
- **病句**
  1. 搭配不当
  2. 成分残缺/赘余
  3. 结构混乱
  4. 表意不明
  5. 逻辑错误
- **修辞**
  1. 比喻/拟人
  2. 借代/借喻

### 5.1 五步图 (看 → 答 → 评 → 学 → 存)

```
[看] 看题 (题干 + 选项 + 关联考点)
    ↓ 答题

    ↓ 提交
[评] 显示对错 + 解释 + 关联考点链接
    ↓ 错题归档
[学] 进错题本: 重新做 1 次 + 关联 3 题
    ↓ 入仓
[存] IndexedDB: wendao_save_v3 增量写入; knowledge_state 矩阵更新
```

### 5.2 错题本 schema (`wendao_save_v3.wrong_book`)

```json
{
  "qid": "uuid",
  "firstSeenAt": 1724080000000,
  "lastSeenAt": 1724200000000,
  "repetitionCount": 3,
  "easiness": 2.3,
  "intervalDays": 7,
  "dueAt": 1724800000000,
  "tags": ["物理", "力学", "牛顿第二定律"]
}
```

使用的算法: SM‑2 变形, 但 `easiness` 受答错次数 × 当前难度系数 (1–5) 反推; `dueAt = lastSeenAt + intervalDays * 86400000`。

### 5.3 推送路径

- **每日 3 题**: 选当日 `easiness < 2.0` 的错题按时间最接近 `dueAt` 的 top 3。
- **每周 1 复盘**: 周日 22:00 自动汇总本周新增错题数 / 已掌握数 / 复习率, 展示"问道路"折线。
- **学期汇总**: 模拟考 / 期中 / 期末前后, 自动出"高频错题 50 题"包, 引导做 1 套完整副本。

## 7. 状态机 / 存档双轨迁移

### 7.1 v2 → v3 一次性迁移 (≤50 行伪代码)

```
function bootV5():
  raw = readLocal("wendao_save_v2")
  save = createV3Default()
  if raw exists:
    v2 = JSON.parse(raw) || {}
    ts = Date.now()
    writeLocal("wendao_save_v3_migration_" + ts, raw)
    save.char = merge(v2.char, defaultChar())
    save.pets = merge(v2.pets || [], v5DefaultPets())
    save.equipment = merge(v2.equipment || [], defaultEquip())
    save.knowledge = {}
    forEach(v2.wrongBook || [], q -> save.knowledge[q.points[0]] = makePointState(q))
    save.completedRealms = v2.realms || []
    save.arenaStats = v2.arena || {easy:0,normal:0,hard:0,boss:0,legend:0}
    save.achievements = v2.achievements || []
    save.feisheng = {bestFloor: v2.feishengBestFloor || 0}
    save.settings = merge(v2.settings, defaultSettings())
    save.schemaVersion = 3
    write("wendao_save_v3", JSON.stringify(save))
    leaveLocal("wendao_save_v2")  # 标记已迁, 不删
  else:
    initFresh()
  startV5App()
```
