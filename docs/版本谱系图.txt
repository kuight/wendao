六、为什么不依赖版本号
================================================================================

修真分支 vs 主分支 = 两套版本号体系:

  修真  : v2.2 -> v3.0 -> v4.0 -> v4.1-hotfix   (线性递增, 修真线编号)
  主分支: v4.3.5f -> g -> h -> i -> j -> v4.3.6 -> 6a -> 6b-p7 -> v4.4.0
                                                 (非线性, 实验平行)
  主分支版本号并非严格单调: 2026-07-05 一天内 v4.3.6 -> v4.3.6-final ->
  v4.3.5f -> v4.3.6a 四个不同版本共存, 互不构成"升级"关系.
  v4.3.5f (12:00) 与 v4.3.6 (09:47) 之间存在时间倒挂,
  但修真 vs 主分支判定仍正确: 修真节点 mtime ≤ 2026-07-03, 主分支 mtime ≥ 2026-07-05.

修真资产 + 主分支版本号交叉: 
  修真-v4.1 (2026-07-03) vs 主分支 v4.3.6 (2026-07-05) 跨日,
  仅看 "v4.1 vs v4.3" 会得出修真 < 主, 但修真专属资产最终被纳入
  主分支更晚的 wendao4.4.0 (2026-07-22). 仅看版本号无法捕捉这一迁入.

以 mtime 为证据的好处:
  - mtime 由 zip 内每文件实际修改时间决定, 无作者主观编号错误影响
  - 可直接按 mtime 排序, 不依赖任何"声明"
  - mtime 分段 (修真 ≤ 07-03, 主线 ≥ 07-05) 比版本号更可靠
  - 完成度证据 (修真专属 JS 模块) 独立于版本号存在, 用修真专属模块
    出现与否判定修真归属, 更准确
